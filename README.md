# GoMRPL Weekly Bot

Готовый проект для еженедельной афиши Telegram-канала `@gomrpl`. По понедельникам он:

1. определяет текущую неделю по часовому поясу `Europe/Moscow`;
2. собирает события с `mariupol.qtickets.events` и `quicktickets.ru/mariupol-dramaticheskiy-teatr`;
3. на `kinoteatr-savona.ru` берёт только релизы из отдельного блока «Скоро в кино», дата старта которых попадает в понедельник—воскресенье текущей недели;
4. удаляет дубли, сортирует события по дню и времени;
5. генерирует квадратную тёмно-синюю/оранжевую обложку и Telegram-разметку в стиле канала;
6. публикует результат через Bot API или сохраняет его локально в безопасном `DRY_RUN`.

## Как работает фильтр кинопремьер

Надпись «Премьера» в текущем расписании «Савоны» может сохраняться дольше одной недели. Поэтому бот не доверяет этому бейджу и берёт кандидатов только из отдельного блока `Скоро в кино`, где у каждого релиза есть дата `с …`. Бот сравнивает её с текущей неделей. Задача запускается в понедельник, до обычного четвергового обновления проката, поэтому премьеры этой недели ещё находятся именно в этом блоке. Фильмы прошлых недель из текущего расписания не попадут в пост.

## Ограничение Telegram, которое важно знать

Bot API разрешает до 1024 видимых символов в подписи к фотографии и до 4096 в обычном сообщении. Основной формат проекта компактный и старается уложить все события в одну подпись под обложкой. Если событий слишком много, бот публикует обложку с коротким вступлением, а полную подборку — следующим сообщением. Это безопаснее, чем обрезать события.

## 1. Создание Telegram-бота

1. Откройте `@BotFather` в Telegram.
2. Отправьте `/newbot`, задайте имя и username.
3. Скопируйте токен вида `123456789:AA...`. Никому его не пересылайте и не добавляйте в GitHub-код.
4. Откройте настройки канала `@gomrpl` → **Администраторы** → **Добавить администратора**.
5. Добавьте созданного бота и включите право **Публиковать сообщения**. Права на удаление и управление администраторами ему не нужны.

Для тестов удобно узнать свой личный `chat_id`:

1. Напишите созданному боту `/start`.
2. В браузере откройте `https://api.telegram.org/botВАШ_ТОКЕН/getUpdates`.
3. Найдите `message.chat.id`. Это значение для `REVIEW_CHAT_ID`.
4. После проверки отзовите старый токен через BotFather, если он случайно попал в историю браузера/скриншот, и создайте новый.

## 2. Локальная проверка

Нужны Node.js 22+ и Git.

```bash
cp .env.example .env
npm install
npx playwright install chromium
```

В `.env` пока оставьте:

```dotenv
DRY_RUN=true
ALLOW_ANY_DAY=true
PUBLISH_TARGET=review
```

Запустите:

```bash
npm run dry-run
```

В папке `out/` появятся:

- `gomrpl-YYYY-MM-DD.jpg` — обложка;
- `gomrpl-YYYY-MM-DD.txt` — текст без Telegram HTML;
- `gomrpl-YYYY-MM-DD.html.txt` — финальная разметка;
- `events-YYYY-MM-DD.json` — всё, что нашли парсеры, и ошибки отдельных источников.

Проверьте дату, названия, возрастные ограничения, адреса и ссылки. Сайты могут менять разметку, поэтому первый живой запуск всегда делайте в личный чат (`PUBLISH_TARGET=review`), а не сразу в канал.

Если тест запускается после четверга, часть уже стартовавших киноновинок может больше не находиться в блоке «Скоро в кино». Это нормально для внепланового прогона: боевой cron работает в понедельник, когда премьеры предстоящей недели ещё показаны в этом блоке. Театр и Qtickets при ручном запуске продолжают фильтроваться по датам всей текущей недели.

## 3. GitHub-репозиторий

1. Создайте приватный репозиторий, например `gomrpl-weekly-bot`.
2. Загрузите все файлы проекта. Файл `.env` загружать нельзя — он уже внесён в `.gitignore`.
3. Убедитесь, что `README.md`, `Dockerfile`, `railway.json`, `package.json`, папки `src/`, `test/` и `.github/` находятся в корне репозитория.

Команды для первого push:

```bash
git init
git add .
git commit -m "Add weekly GoMRPL bot"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/gomrpl-weekly-bot.git
git push -u origin main
```

## 4. Рекомендуемый вариант: GitHub + Railway Cron

Railway запускает cron в UTC. Москва — UTC+3, поэтому понедельник 14:00 МСК равен понедельнику 11:00 UTC. В `railway.json` уже прописано:

```text
0 11 * * 1
```

Настройка:

1. В Railway нажмите **New Project** → **Deploy from GitHub repo** и выберите репозиторий.
2. Railway обнаружит `Dockerfile`. Первый build будет дольше обычного: устанавливаются Chromium и системные библиотеки.
3. Откройте сервис → **Variables** и добавьте:

```dotenv
BOT_TOKEN=ваш_токен
TELEGRAM_CHAT_ID=@gomrpl
REVIEW_CHAT_ID=ваш_личный_chat_id
PUBLISH_TARGET=review
DRY_RUN=false
ALLOW_ANY_DAY=true
CAPTION_LIMIT=1000
PAGE_TIMEOUT_MS=35000
STATE_FILE=/data/gomrpl-state.json
```

4. Для защиты от повторной публикации добавьте Railway Volume и смонтируйте его в `/data`. Без volume защита сохранится только до следующего пересоздания контейнера.
5. В **Settings** проверьте **Cron Schedule**: `0 11 * * 1`. Значение из `railway.json` обычно подхватывается автоматически.
6. Выполните ручной запуск сервиса. Результат должен прийти только в личный чат, потому что `PUBLISH_TARGET=review`.
7. Проверьте картинку, даты, все ссылки и логи. После успешного теста измените:

```dotenv
PUBLISH_TARGET=channel
ALLOW_ANY_DAY=false
```

8. Не включайте `FORCE_PUBLISH=true` постоянно: эта переменная отключает защиту от дублей.

Railway ожидает, что cron-задача завершится после работы. Проект именно так и устроен: запустился, собрал данные, отправил пост и закрыл Chromium. Если процесс остаётся активным, следующий запуск Railway может пропустить.

## 5. Альтернатива: только GitHub Actions

Файл `.github/workflows/weekly.yml` уже добавлен. Он использует расписание `0 11 * * 1` (14:00 МСК) и позволяет ручной запуск через **Actions → Weekly GoMRPL poster → Run workflow**.

В GitHub откройте **Settings → Secrets and variables → Actions → New repository secret** и создайте:

- `BOT_TOKEN` — токен BotFather;
- `TELEGRAM_CHAT_ID` — `@gomrpl`;
- `REVIEW_CHAT_ID` — личный chat_id для ошибок.

Перед первым запуском временно измените в workflow `PUBLISH_TARGET: "channel"` на `"review"`. После проверки верните `channel`.

Недостатки варианта без Railway:

- GitHub предупреждает, что scheduled workflow иногда стартует с задержкой, особенно ровно в начале часа;
- локальный `state` между запусками не сохраняется, поэтому повторный ручной запуск может создать дубль;
- cron работает только с последней версией default-ветки.

Для регулярной публикации в канал Railway Cron надёжнее, а GitHub Actions лучше оставить как резервный ручной запуск.

## 6. Безопасный порядок включения

1. `DRY_RUN=true`, `ALLOW_ANY_DAY=true` — только локальные файлы.
2. `DRY_RUN=false`, `PUBLISH_TARGET=review` — реальная отправка в личный чат.
3. `PUBLISH_TARGET=channel`, `ALLOW_ANY_DAY=false` — боевой режим, публикация только по понедельникам.

Если источник недоступен, бот продолжит работу с остальными и запишет ошибку в JSON/логи. Если недоступны все источники или не найдено ни одного события, публикация отменяется и в `REVIEW_CHAT_ID` уходит предупреждение.

## 7. Как менять оформление

Цвета, размеры, сетка и подписи обложки находятся в `src/cover.js`. Сейчас шаблон повторяет визуальный язык канала: тёмный фон, оранжевый акцент, крупный белый заголовок, диапазон дат, две колонки событий и подпись `@gomrpl`.

Текст поста находится в `src/formatter.js`. Пустые строки формируются явно через двойной `\n\n`, поэтому Telegram сохраняет отступы между заголовком, лидом, днями и финальной ссылкой.

Для более точного совпадения с текущей обложкой положите исходный фон в `assets/background.jpg`, а логотип на прозрачном фоне — в `assets/logo.png`. Бот подхватит их автоматически, затемнит фон для читаемости и оставит динамические даты/события поверх. Без этих файлов используется встроенный шаблон. Сам парсер и расписание от оформления не зависят.

## 8. Обслуживание

Раз в 2–4 недели просматривайте Railway logs. Если один из сайтов изменит CSS-классы, в `events-*.json` появится пустой источник или ошибка. Основные селекторы находятся в `src/scrapers.js`:

- Qtickets: `time[datetime]`, `h2`, `.place-name`, `.price`;
- QuickTickets: `.elem[data-elem-type="event"]`, `.sessions`;
- «Савона»: `a.releases-item_soon`, `.releases-item__date`, `.releases-item__premiere`.

Перед любым изменением запускайте `npm run check` и затем тестовый `PUBLISH_TARGET=review`.
